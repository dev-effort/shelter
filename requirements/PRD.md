# Product Requirements Document (PRD)

## 1. 제품 개요

### 1.1 제품명

**Shelter**

### 1.2 제품 비전

Shelter는 사용자가 웹에서 발견한 유용한 링크들을 체계적으로 정리하고 관리할 수 있는 모바일 링크 관리 애플리케이션입니다. 폴더 구조 기반의 직관적인 UI와 태그 시스템을 통해 사용자는 자신만의 디지털 북마크 라이브러리를 구축할 수 있습니다.

### 1.3 제품 목표

- 링크를 효율적으로 카테고리화하고 저장하는 사용자 친화적인 환경 제공
- 다양한 소셜 미디어 및 앱에서의 원활한 링크 공유 지원
- 빠르고 직관적인 링크 검색 및 필터링 기능 제공
- 광고 수익 모델을 통한 무료 서비스 제공

## 2. 대상 사용자

### 2.1 Primary Users

- 온라인에서 많은 정보를 수집하는 직장인
- 학습 자료를 체계적으로 정리하고 싶은 학생
- 다양한 콘텐츠를 큐레이션하는 크리에이터
- 북마크를 효율적으로 관리하고 싶은 모든 모바일 사용자

### 2.2 사용자 페인 포인트

- 브라우저 북마크만으로는 체계적인 관리가 어려움
- 모바일에서 링크를 카테고리별로 정리하는 전용 앱의 부재
- SNS 앱에서 저장한 링크를 찾기 어려움
- 태그나 폴더로 필터링할 수 있는 기능의 필요성

## 4. 핵심 기능 요구사항

### 4.1 폴더 구조 관리

**기능 설명**: 사용자는 계층적 폴더 구조를 생성하고 관리할 수 있습니다.

**세부 요구사항**:

- 폴더 생성, 수정, 삭제 기능
- 폴더 이름 변경 기능
- 계층 구조 지원 (폴더 내 서브폴더 생성 가능)
- 폴더 간 이동 및 정렬 기능
- 폴더 아이콘 또는 색상 커스터마이징 (선택사항)

**우선순위**: High

### 4.2 링크 메타데이터 저장

**기능 설명**: 각 링크는 다음의 메타정보를 포함합니다.

**메타정보 필드**:

- **제목** (필수): 링크의 제목
- **URL** (필수): 링크 주소
- **설명** (선택): 링크에 대한 상세 설명
- **태그** (선택): 복수 개의 태그 지정 가능

**세부 요구사항**:

- 링크 추가 시 자동으로 웹페이지의 제목 추출 (Open Graph 메타데이터 활용)
- 썸네일 이미지 자동 추출 및 표시 (선택사항)
- 사용자가 모든 필드를 수동으로 편집 가능
- 생성 날짜/수정 날짜 자동 저장

**우선순위**: High

### 4.3 태그 기반 필터링

**기능 설명**: 사용자는 태그를 활용하여 링크를 필터링하고 검색할 수 있습니다.

**세부 요구사항**:

- 태그 자동완성 기능
- 복수 태그 동시 필터링 (AND/OR 조건)
- 태그별 링크 개수 표시
- 자주 사용하는 태그 추천
- 태그 관리 화면 (전체 태그 목록 및 수정/삭제)

**우선순위**: High

### 4.4 링크 열기 (Deep Linking)

**기능 설명**: URL을 탭하면 적절한 방식으로 링크를 엽니다.

**세부 요구사항**:

- 인앱 브라우저가 지원되는 앱 (YouTube, Instagram, Twitter 등)이 설치되어 있으면 해당 앱으로 열기
- 해당 앱이 없으면 시스템 기본 브라우저로 열기
- URL 스키마 검증 및 처리
- 사용자 설정에서 기본 열기 방식 선택 가능 (항상 앱 우선 / 항상 브라우저)

**기술적 고려사항**:

- iOS: Universal Links, Custom URL Schemes
- Android: App Links, Intent Filters

**우선순위**: High

### 4.5 외부 공유 기능 (Share Extension)

**기능 설명**: 다른 앱에서 "공유하기"를 통해 Shelter 앱으로 링크를 직접 저장할 수 있습니다.

**사용자 플로우**:

1. 외부 앱(YouTube, Instagram, 브라우저 등)에서 "공유하기" 선택
2. 공유 대상 목록에서 "Shelter" 선택
3. Shelter 앱이 열리며 다음 화면 표시:
   - 공유된 링크 자동 입력
   - 제목 자동 추출 (수정 가능)
   - 설명 입력란
   - 폴더 선택 드롭다운
   - 새 폴더 생성 버튼
   - 태그 입력란
4. 저장 버튼 클릭 시 선택한 폴더에 링크 저장

**세부 요구사항**:

- iOS Share Extension 구현
- Android Intent Filter 구현
- 빠른 저장을 위한 최소한의 입력 UI
- 최근 사용한 폴더 우선 표시
- 저장 완료 후 토스트 메시지 표시

**우선순위**: High

### 4.6 검색 기능

**기능 설명**: 저장된 링크를 빠르게 찾을 수 있습니다.

**세부 요구사항**:

- 제목, URL, 설명, 태그를 대상으로 전체 검색
- 실시간 검색 결과 표시
- 검색 히스토리 저장
- 고급 검색 옵션 (폴더 내 검색, 날짜 범위 등)

**우선순위**: Medium

### 4.7 정렬 및 보기 옵션

**기능 설명**: 사용자는 다양한 방식으로 링크를 정렬하고 볼 수 있습니다.

**세부 요구사항**:

- 정렬 옵션: 최신순, 오래된 순, 제목순, 사용자 지정 순서
- 보기 옵션: 리스트 뷰, 그리드 뷰
- 사용자 설정 저장

**우선순위**: Low

## 5. 비기능적 요구사항

### 5.1 성능

- URL 유효성 검증
- XSS 공격 방지

### 5.4 접근성

- 최소 폰트 크기 지원

## 7. 화면 구성

### 7.1 메인 화면 (홈)

- 상단: Google 광고 배너
- 검색 바
- 폴더 트리 구조 또는 폴더 그리드
- 하단 네비게이션 바: 홈, 태그, 검색, 설정

### 7.2 폴더 상세 화면

- 폴더 경로 브레드크럼
- 서브폴더 목록
- 링크 리스트 (썸네일, 제목, 설명 미리보기)
- 정렬/필터 버튼
- 플로팅 액션 버튼: 링크 추가, 폴더 추가

### 7.3 링크 추가/편집 화면

- 제목 입력
- URL 입력
- 설명 입력 (멀티라인)
- 폴더 선택
- 태그 입력 (칩 형태)
- 저장/취소 버튼

### 7.4 태그 화면

- 모든 태그 목록 (태그별 링크 개수 표시)
- 태그 선택 시 해당 태그의 링크 목록 표시

### 7.5 설정 화면

- 링크 열기 방식 설정
- 보기 옵션 설정
- 데이터 백업/복원 (Phase 2)
- 앱 정보 (버전, 라이선스 등)

## 8. 사용자 시나리오

### 시나리오 1: 유튜브 영상 저장

1. 사용자가 유튜브 앱에서 흥미로운 영상 발견
2. 공유 버튼 클릭 → "Shelter" 선택
3. Shelter 앱이 열리고 영상 제목과 URL이 자동 입력됨
4. "나중에 볼 영상" 폴더 선택
5. 태그 "교육", "과학" 추가
6. 저장 버튼 클릭
7. "링크가 저장되었습니다" 토스트 메시지 표시

### 시나리오 2: 저장된 링크 검색 및 열기

1. 사용자가 Shelter 앱 실행
2. 상단 검색 바에 "리액트" 입력
3. 관련 링크들이 실시간으로 필터링되어 표시
4. 원하는 링크 탭
5. 브라우저에서 해당 페이지가 열림

### 시나리오 3: 폴더 구조 정리

1. 사용자가 메인 화면에서 "개발" 폴더 확인
2. 폴더 옵션 메뉴에서 "서브폴더 추가" 선택
3. "React", "Node.js", "Python" 서브폴더 생성
4. 기존 링크들을 드래그 앤 드롭으로 적절한 서브폴더로 이동 (또는 편집 화면에서 폴더 변경)

## 9. 개발 가이드라인

### 9.1 코드 컨벤션

- **컴포넌트 분리**: 모든 컴포넌트는 로직적인 최소 단위로 파일 단위로 분리
- **파일 구조**:
  ```
  src/
  ├── components/
  │   ├── common/           # 재사용 가능한 공통 컴포넌트
  │   ├── folder/           # 폴더 관련 컴포넌트
  │   ├── link/             # 링크 관련 컴포넌트
  │   └── tag/              # 태그 관련 컴포넌트
  ├── pages/                # 화면 단위 페이지
  ├── hooks/                # 커스텀 훅
  ├── services/             # API 및 비즈니스 로직
  ├── store/                # 상태 관리
  ├── types/                # TypeScript 타입 정의
  └── utils/                # 유틸리티 함수
  ```

### 9.2 컴포넌트 설계 원칙

- 단일 책임 원칙 (SRP): 하나의 컴포넌트는 하나의 기능만 담당
- Props와 State를 명확히 구분
- 재사용 가능한 UI 컴포넌트와 비즈니스 로직 컴포넌트 분리
- TypeScript 타입을 모든 Props와 State에 정의

### 9.3 네이밍 컨벤션

- 컴포넌트 파일: PascalCase (예: `FolderCard.tsx`)
- 훅 파일: camelCase with 'use' prefix (예: `useFolders.ts`)
- 유틸리티 함수: camelCase (예: `formatDate.ts`)
- 타입/인터페이스: PascalCase (예: `LinkMetadata.ts`)

### 9.4 TypeScript 사용 가이드

- `any` 타입 사용 금지
- 엄격한 타입 체크 활성화
- 인터페이스 정의 우선, 필요시 타입 별칭 사용

## 12. 리스크 및 대응 방안

### 리스크 1: Share Extension 구현 복잡도

- **대응**: iOS와 Android의 네이티브 기능을 먼저 프로토타입으로 구현하여 기술 검증
- **대안**: 먼저 앱 내 수동 링크 추가 기능을 완성하고, 공유 기능은 Phase 1.5로 연기

### 리스크 2: Deep Linking 호환성 문제

- **대응**: 주요 앱(YouTube, Instagram, Twitter 등) 우선 지원하고 점진적 확대
- **대안**: 사용자가 직접 앱 매핑을 설정할 수 있는 고급 옵션 제공

### 리스크 3: 광고 수익 부족

- **대응**: 사용자 경험을 해치지 않는 선에서 배너 광고 최적화
- **대안**: 프리미엄 버전 출시 또는 선택적 보상형 광고 도입

## 13. 참고사항

- Pocket: 읽기 전용 콘텐츠 저장에 강점

- Material Design 3 (Android) 및 Human Interface Guidelines (iOS) 준수
- shadcn 컴포넌트를 활용한 일관된 디자인 시스템
- 직관적이고 미니멀한 UI
