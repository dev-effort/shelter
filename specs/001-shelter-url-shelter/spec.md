# Feature Specification: Shelter - Link Organization App

**Feature Branch**: `001-shelter-url-shelter`  
**Created**: 2025-10-13  
**Status**: Draft  
**Input**: User description: "shelter앱은 많은 링크(url) 정보를 카테고리화하여 저장하는 앱이다. shelter앱은 폴더구조를 가지고 있다. 폴더들은 계층구조를 가진다. 폴더구조에 저장되는 메타정보는 제목, url, 설명, 태그이다. 태그로 필터링 하여 볼 수 있다. url을 누르면 해당 url을 켤 수 있는 인앱이 있으면 앱을 먼저 키고 없으면 브라우저로 연다. 외부앱 (유튜브, 인스타그램 등)에서 외부앱으로 공유하기를 했을때, shelter앱이 나오고, shelter앱을 선택하면 폴더를 선택하거나, 폴더를 생성하고 선택된 폴더에 제목과 공유된 링크, 설명을 저장한다."

## User Scenarios & Testing

### User Story 1 - 링크 저장 및 폴더 구성 (Priority: P1)

사용자는 수집한 링크들을 폴더 구조로 정리하여 저장할 수 있다. 폴더는 계층적으로 구성되며, 각 링크는 제목, URL, 설명, 태그를 포함한다.

**Why this priority**: 앱의 핵심 가치인 링크 저장과 조직화 기능으로, 이것 없이는 앱의 기본 목적을 달성할 수 없음.

**Independent Test**: 사용자가 앱을 열고 폴더를 생성한 후 링크를 추가하고, 추가된 링크가 폴더 내에서 제목, URL, 설명, 태그와 함께 표시되는지 확인하여 독립적으로 테스트 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 화면에 있을 때, **When** 폴더 생성 버튼을 클릭하면, **Then** 새 폴더가 생성되고 폴더 이름을 입력할 수 있다
2. **Given** 사용자가 폴더 내에 있을 때, **When** 문서 생성 버튼을 클릭하면, **Then** 제목, URL, 설명, 태그를 입력할 수 있는 양식이 표시된다
3. **Given** 사용자가 문서 양식을 작성했을 때, **When** 저장 버튼을 클릭하면, **Then** 해당 폴더에 문서가 저장되고 목록에 표시된다
4. **Given** 사용자가 폴더 내에 있을 때, **When** 하위 폴더를 생성하면, **Then** 계층 구조가 형성되고 상위-하위 관계가 표시된다

---

### User Story 2 - 외부 앱 공유 연동 (Priority: P2)

사용자는 유튜브, 인스타그램 등 외부 앱에서 '공유하기'를 통해 링크를 Shelter 앱으로 바로 저장할 수 있다.

**Why this priority**: 사용자가 다른 앱에서 유용한 콘텐츠를 발견했을 때 즉시 저장할 수 있게 하여 사용성을 크게 향상시키는 기능이지만, 기본 저장 기능이 선행되어야 함.

**Independent Test**: 외부 앱(예: 유튜브)에서 공유 버튼을 누르고 Shelter 앱을 선택한 후, 폴더를 선택하거나 생성하여 링크가 저장되는지 확인하여 독립적으로 테스트 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 외부 앱에서 콘텐츠를 보고 있을 때, **When** 공유 버튼을 누르면, **Then** Shelter 앱이 공유 옵션 목록에 표시된다
2. **Given** 사용자가 Shelter 앱을 공유 대상으로 선택했을 때, **When** Shelter 앱이 열리면, **Then** 폴더 선택 화면이 표시되고 공유된 URL이 미리 채워진 양식이 나타난다
3. **Given** 사용자가 폴더 선택 화면에 있을 때, **When** 새 폴더 생성 옵션을 선택하면, **Then** 새 폴더를 생성하고 그곳에 바로 저장할 수 있다
4. **Given** 사용자가 폴더를 선택했을 때, **When** 제목과 설명을 입력하고 저장하면, **Then** 해당 폴더에 링크가 저장된다

---

### User Story 3 - 링크 열기 및 실행 (Priority: P3)

사용자는 저장된 링크를 클릭하여 해당 콘텐츠에 접근할 수 있다. 링크에 대응하는 앱이 설치되어 있으면 해당 앱으로 열고, 없으면 브라우저로 연다.

**Why this priority**: 저장된 링크에 접근하는 기능은 중요하지만, 링크 저장 기능이 먼저 구현되어야 함.

**Independent Test**: 저장된 유튜브 링크를 클릭하여 유튜브 앱이 열리는지, 일반 웹사이트 링크는 브라우저로 열리는지 확인하여 독립적으로 테스트 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 저장된 링크 목록을 보고 있을 때, **When** 유튜브 링크를 클릭하고 유튜브 앱이 설치되어 있으면, **Then** 유튜브 앱으로 해당 콘텐츠가 열린다
2. **Given** 사용자가 저장된 링크 목록을 보고 있을 때, **When** 일반 웹사이트 링크를 클릭하면, **Then** 기본 브라우저로 해당 페이지가 열린다
3. **Given** 사용자가 저장된 링크 목록을 보고 있을 때, **When** 인스타그램 링크를 클릭하고 앱이 설치되어 있지 않으면, **Then** 브라우저로 해당 페이지가 열린다

---

### User Story 4 - 태그 필터링 (Priority: P3)

사용자는 태그를 통해 저장된 링크를 필터링하고 관련된 콘텐츠를 빠르게 찾을 수 있다.

**Why this priority**: 링크가 많아질수록 유용한 기능이지만, 기본 저장 및 조직화 기능이 먼저 구현되어야 함.

**Independent Test**: 여러 링크에 동일한 태그를 추가한 후, 태그 화면에서 해당 태그를 선택하여 필터링된 결과가 올바르게 표시되는지 확인하여 독립적으로 테스트 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 네비게이션에서 태그를 선택했을 때, **When** 태그 화면이 열리면, **Then** 사용 중인 모든 태그 목록이 표시된다
2. **Given** 사용자가 태그 목록을 보고 있을 때, **When** 특정 태그를 클릭하면, **Then** 해당 태그가 지정된 모든 문서가 표시된다
3. **Given** 사용자가 태그로 필터링된 결과를 보고 있을 때, **When** 문서를 클릭하면, **Then** 문서 상세 화면이 열린다

---

### User Story 5 - 검색 기능 (Priority: P3)

사용자는 검색 기능을 통해 제목, URL, 설명 등에서 키워드를 찾아 원하는 링크를 빠르게 찾을 수 있다.

**Why this priority**: 링크 수가 증가할 때 유용하지만, 기본 저장 및 조직화 기능이 선행되어야 함.

**Independent Test**: 여러 링크를 저장한 후 검색 화면에서 특정 키워드를 입력하여 관련 결과가 표시되는지 확인하여 독립적으로 테스트 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 네비게이션에서 검색을 선택했을 때, **When** 검색 화면이 열리면, **Then** 검색어 입력 필드가 표시된다
2. **Given** 사용자가 검색 화면에 있을 때, **When** 검색어를 입력하면, **Then** 제목, URL, 설명에 해당 키워드가 포함된 문서들이 실시간으로 표시된다
3. **Given** 사용자가 검색 결과를 보고 있을 때, **When** 결과를 클릭하면, **Then** 해당 문서 상세 화면이 열린다

---

### User Story 6 - 문서 및 폴더 삭제 (Priority: P3)

사용자는 더 이상 필요하지 않은 문서나 폴더를 삭제할 수 있다.

**Why this priority**: 관리 기능으로 중요하지만, 생성 및 조회 기능이 먼저 구현되어야 함.

**Independent Test**: 폴더나 문서를 길게 눌러 삭제 팝업이 나타나고 삭제 확인 후 해당 항목이 목록에서 제거되는지 확인하여 독립적으로 테스트 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 화면에서 폴더나 문서를 보고 있을 때, **When** 항목을 길게 누르면, **Then** 삭제 확인 팝업이 표시된다
2. **Given** 사용자가 삭제 확인 팝업을 보고 있을 때, **When** 삭제를 확인하면, **Then** 해당 항목이 목록에서 제거된다
3. **Given** 사용자가 하위 항목이 있는 폴더를 삭제하려고 할 때, **When** 삭제를 확인하면, **Then** 해당 폴더와 모든 하위 항목(하위 폴더 및 문서)이 함께 삭제되며, 삭제 확인 팝업에는 삭제될 항목 수에 대한 경고가 표시된다

---

### User Story 7 - 홈 화면 표시 설정 (Priority: P4)

사용자는 홈 화면에서 폴더와 문서를 리스트 구조 또는 그리드 구조로 볼 수 있으며, 설정에서 표시 방식을 변경할 수 있다.

**Why this priority**: 사용자 경험 개선 기능이지만, 핵심 기능이 아니므로 가장 낮은 우선순위.

**Independent Test**: 설정 화면에서 표시 방식을 변경한 후 홈 화면으로 돌아가 실제로 리스트/그리드 구조가 변경되는지 확인하여 독립적으로 테스트 가능.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 화면에 있을 때, **When** 화면이 로드되면, **Then** 설정된 표시 방식(리스트 또는 그리드)으로 폴더와 문서가 표시된다
2. **Given** 사용자가 네비게이션에서 설정을 선택했을 때, **When** 설정 화면이 열리면, **Then** 리스트/그리드 구조 선택 옵션이 표시된다
3. **Given** 사용자가 설정 화면에서 표시 방식을 변경했을 때, **When** 홈 화면으로 돌아가면, **Then** 변경된 표시 방식이 적용되어 있다
4. **Given** 사용자가 폴더를 리스트 또는 그리드로 보고 있을 때, **When** 폴더를 보면, **Then** 폴더 내 링크 개수와 하위 폴더 개수가 메타정보로 표시된다

---

### Edge Cases

- 사용자가 잘못된 형식의 URL을 입력하면 어떻게 되는가?
- 폴더 깊이에 제한이 있는가? (예: 최대 10단계까지만 허용)
- 동일한 URL을 여러 폴더에 저장할 수 있는가?
- 폴더나 문서 이름이 비어있거나 너무 길면 어떻게 처리하는가?
- 외부 앱에서 공유할 때 네트워크 연결이 없으면 어떻게 되는가?
- 태그가 없는 문서는 태그 화면에서 어떻게 표시되는가?
- 검색어가 비어있을 때는 어떤 결과를 보여주는가?
- 광고가 로드되지 않으면 레이아웃은 어떻게 처리되는가?

## Requirements

### Functional Requirements

- **FR-001**: 시스템은 사용자가 새 폴더를 생성할 수 있어야 한다
- **FR-002**: 시스템은 폴더 내에 하위 폴더를 생성하여 계층 구조를 형성할 수 있어야 한다
- **FR-003**: 시스템은 폴더 내에 문서(링크)를 생성할 수 있어야 한다
- **FR-004**: 각 문서는 제목, URL, 설명, 태그를 포함해야 한다
- **FR-005**: 시스템은 외부 앱의 공유 기능에서 Shelter 앱을 공유 대상으로 표시해야 한다
- **FR-006**: 시스템은 외부 앱에서 공유된 URL을 수신하고 사용자에게 폴더 선택 또는 생성 옵션을 제공해야 한다
- **FR-007**: 시스템은 저장된 링크를 클릭할 때 해당 URL에 대응하는 앱이 있으면 해당 앱으로, 없으면 브라우저로 열어야 한다
- **FR-008**: 시스템은 모든 태그 목록을 표시하고 특정 태그를 선택하면 해당 태그가 지정된 문서만 필터링하여 표시해야 한다
- **FR-009**: 시스템은 검색 기능을 제공하고 제목, URL, 설명에서 키워드를 찾아야 한다
- **FR-010**: 시스템은 홈 화면에서 폴더와 문서를 리스트 또는 그리드 구조로 표시해야 한다
- **FR-011**: 시스템은 설정 화면에서 리스트/그리드 표시 방식을 변경할 수 있어야 한다
- **FR-012**: 시스템은 폴더 또는 문서를 길게 누르면 삭제 확인 팝업을 표시해야 한다
- **FR-013**: 시스템은 사용자가 삭제를 확인하면 해당 폴더 또는 문서를 영구적으로 제거해야 한다
- **FR-013-1**: 시스템은 하위 항목이 있는 폴더를 삭제할 때 모든 하위 폴더와 문서를 함께 삭제해야 한다 (cascade delete)
- **FR-013-2**: 시스템은 하위 항목이 있는 폴더 삭제 확인 팝업에 삭제될 총 항목 수를 경고로 표시해야 한다
- **FR-014**: 시스템은 홈 화면에서 폴더를 표시할 때 폴더 내 링크 개수와 하위 폴더 개수를 메타정보로 표시해야 한다
- **FR-015**: 시스템은 설정 화면에서 앱 버전 정보를 표시해야 한다
- **FR-016**: 시스템은 화면 상단에 광고 영역을 표시해야 한다
- **FR-017**: 시스템은 하단에 홈, 태그, 검색, 설정으로 이동할 수 있는 네비게이션을 제공해야 한다
- **FR-018**: 시스템은 헤더에 폴더 생성 버튼과 문서 생성 버튼을 표시해야 한다

### Key Entities

- **폴더(Folder)**: 링크와 하위 폴더를 담는 컨테이너. 이름, 생성일, 상위 폴더 참조, 하위 항목 개수 정보를 포함
- **문서(Document/Link)**: 저장된 링크 정보. 제목, URL, 설명, 태그 목록, 생성일, 소속 폴더 참조를 포함
- **태그(Tag)**: 문서를 분류하는 레이블. 태그 이름과 해당 태그가 지정된 문서들의 참조를 포함

## Success Criteria

### Measurable Outcomes

- **SC-001**: 사용자는 외부 앱에서 링크를 Shelter 앱으로 공유하여 3번의 탭 이내에 저장을 완료할 수 있다
- **SC-002**: 사용자는 저장된 링크 중 원하는 링크를 검색 또는 태그 필터링을 통해 5초 이내에 찾을 수 있다
- **SC-003**: 시스템은 100개 이상의 폴더와 1,000개 이상의 링크를 저장하고 표시할 수 있다
- **SC-004**: 사용자의 80% 이상이 저장한 링크를 일주일 내에 1회 이상 재방문한다
- **SC-005**: 저장된 링크를 클릭했을 때 1초 이내에 해당 앱 또는 브라우저가 열린다
- **SC-006**: 사용자는 리스트/그리드 표시 방식을 변경하고 즉시 반영된 화면을 볼 수 있다

## Assumptions

- 사용자는 모바일 기기(iOS 또는 Android)를 사용한다고 가정
- 광고는 Google AdMob 또는 유사한 광고 네트워크를 통해 제공된다고 가정
- 외부 앱 공유 연동은 플랫폼의 표준 공유 인터페이스를 사용한다고 가정
- 링크 열기 기능은 운영 체제의 딥링크 및 인텐트 시스템을 활용한다고 가정
- 데이터는 사용자 기기에 로컬 저장되며, 클라우드 동기화는 이 기능 범위에 포함되지 않음
- URL 유효성 검사는 기본적인 형식 검증 수준으로 제한됨 (정확한 URL 접근 가능 여부는 확인하지 않음)
